# 윈도우 검증 1단계: 이름 부르기 + 실시간 받아쓰기

윈도우판을 만들기 전에 가장 큰 걸림돌 하나만 먼저 확인하는 도구입니다.
**"사사리사" 하고 부르면 맥만큼 빨리 알아듣는가?** 이게 안 되면 나머지는 옮겨도 의미가 없습니다.

맥판은 애플 기기 안 음성인식을 씁니다(`Ear.swift`). 윈도우에는 그만큼 쓸 만한 한국어 인식이 기본으로 없어서,
여기서는 무료 오픈소스 엔진 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)의 한국어 실시간 모델로 대신해 봅니다.
인터넷 없이 PC 안에서만 돌아갑니다.

## 무엇을 비교하나
두 가지 방식을 동시에 돌리고, 어느 쪽이 더 빨리·정확히 알아듣는지 나란히 보여 줍니다.

| 이름 | 방식 | 비고 |
|---|---|---|
| `asr` | 실시간 받아쓰기 글자에서 이름 패턴을 찾음 | 맥과 같은 방식입니다. `Config.soundAlike`, `Parser.wakeRange` 규칙을 그대로 옮겼습니다 |
| `kws` | 같은 모델로 "사사리사" 소리만 따로 찾는 감지기 | 맥에는 없는 방식입니다. 사전에 없는 지어낸 이름에 강할 것으로 기대됩니다 |

**감지 지연**은 "이름을 알아들은 순간 − 목소리가 끝난 순간"입니다. 음수면 말하는 도중에 이미 알아들은 것입니다.

## 설치 (한 번만)
1. 파이썬이 없으면 설치합니다: `winget install Python.Python.3.12`
2. 이 폴더(`windows\poc`)에서 PowerShell을 열고 실행합니다.
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\setup.ps1
   ```
   모델을 약 420 MB 내려받습니다.

## 측정 순서
아래 명령의 `py`는 `.\.venv\Scripts\python.exe`를 뜻합니다.

| 단계 | 명령 | 할 일 |
|---|---|---|
| 0. 마이크 확인 | `py wake_poc.py devices` | 쓸 마이크 번호를 확인합니다. 이후 명령에 `--device 번호`를 붙입니다 |
| 1. 실시간 체감 | `py wake_poc.py mic` | 「사사리사」, 「사사리사 유튜브 틀어」를 여러 번 말해 봅니다. 끝내려면 Ctrl+C |
| 2. 가까이서 녹음 | `py wake_poc.py record 10 --tag near` | 평소 자리에서 이름만 10번 말합니다 |
| 3. 멀리서 녹음 | `py wake_poc.py record 10 --tag far` | 방 건너편에서 10번 말합니다 |
| 4. 녹음으로 재측정 | `py wake_poc.py wav "samples\*.wav"` | 녹음해 둔 소리로 같은 조건에서 다시 잽니다. 설정을 바꿔 가며 비교할 때 씁니다 |
| 5. 잘못 깨기 | `py wake_poc.py mic` 켜 둔 채 유튜브·대화 10분 | 이름을 안 불렀는데 `▶ 감지`가 몇 번 뜨는지 셉니다 |

결과는 `results\` 폴더에 CSV로 저장됩니다. 녹음 파일(`samples\`)과 함께 보내 주시면 같이 분석할 수 있습니다.

## 통과 기준 (제안)
아직 확정된 기준이 아니라 제안값입니다. 맥에서 쓰실 때의 체감과 비교해서 조정하시면 됩니다.

| 항목 | 기준 |
|---|---|
| 감지 지연 (중앙값) | **+0.5초 이하** (이름을 말하고 0.5초 안에 반응) |
| 가까이서 감지율 | 10번 중 **9번 이상** |
| 멀리서 감지율 | 10번 중 **7번 이상** |
| 잘못 깨기 | 10분에 **1번 이하** |
| 처리 속도 | 요약의 RTF가 **0.3 이하**이고 "⚠ 처리가 밀립니다"가 뜨지 않음 |

## 조절할 수 있는 것
| 옵션 | 효과 |
|---|---|
| `--kw-threshold 0.05` | kws가 더 잘 잡습니다. 대신 잘못 깨기가 늘 수 있습니다 (기본 0.1) |
| `--kw 샤샤리샤 사사리싸` | 실제로 잘못 들리는 소리를 kws에 추가합니다 |
| `--no-kws` | 맥과 똑같은 받아쓰기 방식만 씁니다 |
| `--threads 4` | 느린 PC에서 처리 속도를 높입니다 |
| `--fp32` | 원본 모델을 씁니다. 느리지만 조금 더 정확할 수 있습니다 |
| `--name 자비스` | 다른 이름을 시험합니다 |

## 만든 쪽에서 미리 확인한 것
리눅스 클라우드 환경(CPU 4코어)에서 미리 돌려 봤습니다. 윈도우 실기기와 실제 목소리 측정은 아직 하지 않았습니다.

- **처리 속도:** 0.1초 소리를 평균 약 20 ms에 처리했습니다(RTF 0.20). 노트북 CPU에서도 여유가 있을 것으로 봅니다.
- **"자비스"로 시험:** `asr`과 `kws` 모두 「자비스 볼륨」을 **말하는 도중에** 알아들었습니다. 일반 문장 4개에서는 잘못 깨지 않았습니다.
- **"사사리사":** 합성 음성으로는 시험하지 못했습니다. 쓸 수 있는 한국어 합성 음성 품질이 낮아서 받아쓰기가 「에세리쎄」, 「해세리작」처럼 나왔기 때문입니다.
  엔진 문제가 아니라 합성 음성 문제여서, **실제 목소리로 재는 것이 이 도구의 핵심 목적**입니다.

## 이 단계에서 다루지 않는 것
- Whisper 정밀 받아쓰기: whisper.cpp는 윈도우에서도 그대로 돌아가서 검증할 필요가 없습니다.
- 명령 실행, 화면 구슬, 카톡: 이 단계를 통과한 뒤에 진행합니다.
