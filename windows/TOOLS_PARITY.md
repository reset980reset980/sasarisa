# 화면 도구 이식 현황

0.2.35: `type`, `fill_field`, `insert_field`가 지원되는 일반 편집칸에 입력한 원문·선택 위치를 실행 기록에 보관합니다. 이후 내용/대상이 바뀌지 않았을 때 ‘되돌려’로 복원합니다. 6,000자 이내이고 UIA Value/Text를 함께 제공하는 일반 Edit 칸만 지원하며 서식 문서는 제외합니다. 확인할 수 없는 입력과 중단된 입력은 앞선 동작으로 건너뛰지 않고 직접 확인을 안내합니다. 원문은 최대 20개 실행 기록의 메모리에만 보관하고 파일로 저장하지 않습니다.

0.2.13은 `kakao_chats`, `kakao_draft`, `kakao_send`, `kakao_send_draft`를 추가하여 45개 도구를 제공합니다. 열린 대화방의 최신 관측 ID만 사용하며 초안·전송 모두 대상/전체 내용 확인창을 거칩니다. 기존 초안과 승인 중 변경을 보존하고, 전송 불확실 시 재전송하지 않습니다. 실제 초안과 취소는 검사했고 전송·배달은 현장 검증하지 않았습니다.

0.2.12의 `display_off`도 유지합니다. AI 실행은 화면 끄기 확인창을 거치며 로컬 명령과 루틴에서도 같은 Windows 전원 요청을 사용합니다. Windows의 세션 화면 꺼짐 알림을 받았을 때만 꺼짐 확인으로 응답합니다.

0.2.11은 Code의 ‘새 세션’ 시작 화면에서도 기존 세션 목록을 읽습니다. 시작 화면 주소는 목록 조회에만 허용하며, 본문 입력·전송은 기존과 동일하게 선택된 세션 주소를 확인한 뒤 실행합니다. 사이드바를 맨 위로 올린 시작 화면에서 아래쪽 프로젝트의 세션을 찾아 전환하는 실제 동작을 검증했습니다.

0.2.10은 `list_sessions`, `switch_session`, `delegate_session`을 추가하여 40개 도구를 제공합니다. 공식 Claude Windows 패키지의 한국어 Code 사이드바에서 관측한 세션만 선택하며, 로컬·클라우드 세션 주소를 확인합니다. 12개씩 조회하고 최신 페이지 ID만 2분간 유효합니다. 전달은 별도 확인창으로 프로젝트·세션·본문을 확인하며, 기존 초안·작업 중 상태·대상 변경·취소 시 중단합니다. 승인 전에는 세션 전환만 수행하고, 승인 후에 본문 입력과 보내기를 한 번 실행합니다. 실제 로컬 세션의 응답과 취소·초안 변경 차단을 확인했습니다. 전송 후 실행 결과와 Claude 자체의 권한 요청은 Claude에서 확인해야 합니다.

0.2.9에서는 Anthropic/OpenAI/Gemini/OpenRouter/Groq/LM Studio/호환 API/Ollama에도 같은 37개 도구를 직접 연결합니다. OpenAI는 Responses, Anthropic은 Messages, 나머지는 Chat Completions 규약을 사용합니다. 호출 ID와 인수를 검증한 뒤 한 번씩 순서대로 실행하고, 승인·대상 창 검사·취소는 Claude/Codex와 같은 실행기를 거칩니다. 이미지 결과도 제공자별 메시지 형식으로 반환합니다. 실제 로컬 HTTP 시험 서버에서 입력칸 조회→입력 승인→이미지 전송 승인과 중간 취소를 검증했으며, 실제 유료 계정·로컬 AI 모델과의 연결 및 시각 판단 품질은 미검증입니다.

0.2.8은 기존 `key`를 복합 단축키와 이동·편집 키로 확장합니다. 대상 창의 키보드 배열로 기호를 변환하고, 확장 키 플래그·보조 키 해제·부분 전달 시 해제를 처리합니다. 확인 중 창/초점 항목 변경, 이미 눌린 키, 등록된 비서 단축키와의 충돌을 검사합니다. 한 호출에 한 조합만 전달하며, 다른 창이 열리면 후속 입력 대상을 해제합니다. MCP 도구 수는 37개입니다.

0.2.7은 `list_windows`, `select_window`, `front`를 추가해 Claude/Codex에 37개 MCP 동작을 제공합니다. 창 목록의 요청별 ID로 기존 창을 선택하고, 전환한 창을 후속 화면·입력 동작의 대상으로 다시 설정합니다. 목록은 12개씩, 현재 요청의 최신 페이지만 2분간 유효합니다. 같은 앱의 다른 창·닫힌 창·변경된 제목을 구분하고 사용자 창 변경을 감지합니다. `front`는 비서 창을 제외한 작업 앱/제목과 읽을 수 있는 브라우저 주소를 반환합니다. API/Ollama의 JSON 계획에서도 같은 창 도구를 사용할 수 있습니다.

0.2.6은 `insert_field`를 추가해 Claude/Codex에 34개 MCP 동작을 제공합니다. 조회한 특정 입력칸의 현재 커서에 글을 넣거나 현재 선택된 부분만 바꾸며 나머지 글을 보존합니다. 전체 교체는 기존 `fill_field`로 구분합니다. 입력 전후 전체 글이 각각 6,000자 이내이고 접근성 API로 하나의 커서·선택 영역을 확인할 수 있어야 합니다. 확인 중 내용·커서·선택이 바뀌면 입력하지 않으며, 긴 입력 중 변경·취소 시 추가 입력을 멈추고 부분 입력 가능성을 안내합니다.

0.2.5는 아래 0.2.4 도구에 `screenshot`과 `click`을 추가해 Claude/Codex에 33개 MCP 동작을 제공합니다. 실제 WPF 그림에서 이미지 확인→클릭 미리보기→파란 원 누르기를 검증했고, 확인 대기 중 초록색으로 바뀐 원에는 클릭이 전달되지 않았습니다. 이미지 ID는 현재 요청의 최신 이미지에만 유효하고 120초 뒤 또는 조작 후 폐기합니다. 이미지 바이트는 이 앱의 대화 기록·로그·임시 파일에 저장하지 않습니다. AI 서비스의 데이터 처리는 해당 제공자의 정책을 따릅니다.

캡처는 선택한 창에 `PrintWindow`를 요청하는 별도 프로세스에서 수행하며 5초 제한과 취소를 적용합니다. 다른 창이나 오버레이를 함께 담는 바탕화면 캡처로 대체하지 않습니다. 클릭은 다시 읽은 창의 위치·제목·픽셀과 누를 위치의 창 소유권·암호 입력 여부를 검사합니다. 영상·보호된 창·일부 GPU 앱은 캡처가 안 될 수 있으며 실제 브라우저·다중 배율 검증은 아직 남아 있습니다. 0.2.9부터 외부 API/Ollama에도 이미지 도구를 제공하며 이미지 입력 지원 모델이 필요합니다.

원본 기준: [`Tools/mcp.swift`](../Tools/mcp.swift), [`Tools/jax.swift`](../Tools/jax.swift). 기능 동작과 MCP 연결 규약을 별도로 확인합니다. 0.2.4의 Claude/Codex는 공식 C# SDK 기반 stdio MCP로 Windows 공통 동작 31개를 호출합니다. 0.2.9의 API/Ollama 연결은 직접 도구 호출을 사용합니다. 원본 macOS 도구 이름·인수를 그대로 제공하는 서버는 아닙니다.

0.2.4의 조회 ID는 현재 요청의 최신 목록 페이지에만 유효하며 2분 뒤 만료됩니다. 조작 뒤 다시 조회해야 합니다. 확인을 기다리는 동안 대상 창·항목·입력 내용이 바뀌면 중단합니다. 입력칸 전체 교체와 항목 누르기는 항상 확인을 받으며, 부분 입력 후 실패·취소는 완료로 기록하지 않습니다.

MCP 연결: `VoiceAssistant.exe --mcp`는 해당 AI 요청에서만 유효한 같은 사용자 전용 named pipe로 실행 중 앱에 연결됩니다. 도구마다 기존 입력 검증·대상 창 고정·확인 UI를 거치며, 병렬 호출도 순차 실행합니다. 거절·창 변경·실행 횟수 초과 뒤에는 추가 호출을 막습니다. 요청 취소와 연결 종료는 대기 중인 확인창에도 전달됩니다. MCP만 실행하면 메인 창을 만들지 않습니다.

실제 별도 프로세스에서 2025-06-18, 2025-11-25, 2026-07-28 연결, 목록·호출·잘못된 인수/도구 오류, 취소, EOF 종료를 검사했습니다. 실제 Claude/Codex가 모의 타이머 목록의 ID를 읽고 지정된 항목만 취소하는 연속 호출도 통과했습니다. 실제 WPF 시험 창에서 Claude의 조회→확인→두 번째 입력칸 한글 교체 및 확인 대기 중 중지 단축키에 따른 창 닫힘·원문 보존을 확인했습니다.

남은 연결 작업: 실제 외부 API 계정/로컬 모델 현장 검증과 위 표의 미구현 원본 도구. [Codex MCP 설정 문서](https://developers.openai.com/codex/config-reference)의 서버별 도구 목록·도구별 승인 설정으로 이 앱의 고정 도구만 연결하며, 앱 안의 사용자 확인은 계속 적용됩니다.
